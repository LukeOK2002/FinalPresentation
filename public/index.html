What are transposable elements

Transposable Elements (TEs) are genetic sequences capable of copying themselves and spreading throughout the genome

Either by creating an RNA intermediate (retrotransposition)...

Or by excising itself (transposition)

Click 1: retrotransposition (copy via RNA, then paste into a new site). Click 2: transposition (cut out, then paste into a new site).

RepeatModeler counts exact k-mer occurrences

These two tools can be used to model repeat families

MADE1/2 investigation

One of these unannotated families was MADE1/MADE2

It’s a short, 80 bp family composed of two palindromic repeats

RepeatMasker’s search found 71 loci without annotation

But a more sensitive BLAST search brought the count up to 378

To ensure these loci were genuine, various tests were used

Shuffling the sequence 500 times and BLASTing it against the reference sequence

Comparing orthologous positions in primates

Querying against profile hidden Markov models

These tests confirmed all but one locus

1: MADE1 = 80 bp, two palindromic (inverted) repeats around a short core. 2: 71 unannotated RepeatMasker hits. 3: BLAST raises it to 378. 5: shuffled sequence (500 shuffles) scores ~1 vs 16 for the real locus. 6: present at the orthologous position in chimpanzee. 7: matches the profile HMM. 8: all confirmed but one.

TSD check

MADE1/MADE2 TEs insert at ‘TA’ positions

Forming 2 bp ‘TA’ TSDs at either side

Searched for ‘TA’ at both sides of the insertion

However, in some cases, the element boundaries were unclear

So, TSDs were searched for within a 6 bp window upstream/downstream of the insertion

Results

The majority do not have detectable TSDs

How do these results compare to background rates?

1: staggered cut at TA, MADE inserts. 2: fill-in gives 2 bp TA TSDs. 3: TA checked either side. 4: boundaries can be ambiguous by a base or so. 5: so a 6 bp window was searched. 6: exact 2 bp 5.82% vs 6 bp window 32.28% with TA on both sides. 7: most have no detectable TSDs. 8: compare to background.

But why were these copies missed in the first place?

A permissive BLAST search found these copies, but RepeatMasker didn’t? Why?

For this, I had to delve into RepeatMasker’s documentation

As it turns out, RepeatMasker’s RMBlast engine requires copies to pass a fixed score threshold to be annotated

However, short elements have fewer total bases, making it harder for them to reach this fixed threshold

Detection is also dependent on the GC % of the surrounding sequence

Using GC % to select the scoring matrix used

RepeatMasker calculates GC % in 56–60 kb batches

This can flip detection outcomes

2: RMBlast needs a Smith–Waterman score ≥ 225. 3: short elements top out below it. 5: GC% picks the scoring matrix. 6: GC is measured over 56–60 kb batches, so the local GC can differ. 7: same copy, 48% GC (60 kb) matrix → 214, missed; 45% GC (1 kb) matrix → 231, detected.
